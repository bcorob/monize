# v1.15.0

The **audit** release.

Monize was put through an eight-phase external review — architecture, authentication, backup and restore, concurrency, financial calculation, investments, release integrity, documentation — and most of this release is the answer to it. Roughly forty of the changes below are remediation: a partial total that reported itself as complete, a logout that said it had worked when it had not, a cron job that ran twice on two replicas, a backup that restored onto rows pointing at nothing.

None of that is visible until it bites, so there is plenty here that is. An **investment account stops being two accounts** on every screen that draws it. **Account Balances** becomes a real point-in-time report with a date on it. **Categories get a detail page**, the **Reconcile screen** learns to edit, sort, group and remind, the **Cash Flow Forecast** takes more than one account, and **CSV import** finally handles brokerage files.

The other half of the audit's answer is that the rules the review found broken are now written down as contracts in `docs/`, with an honest status on each — and where a machine can check one, it does.

## Investments

### One account, not two

An investment account has always been stored as two: a brokerage ledger holding the securities and a linked cash ledger holding the money. Every screen showed you both, as peers, which is not the account you think you have.

It is now one row in the **account list**, under the name you gave it, with a combined value and a caption saying what it is made of. Reconcile targets the cash ledger (it used to be hidden entirely for brokerages), Close and Reopen make one call across both halves, and Delete removes both behind one confirmation. The **detail page** is one page with both registers behind a toggle, the **edit form** finally reaches the cash ledger's opening balance, account number and description, and **pickers, reports and the dashboard** offer the pair as one option.

Two server-side defects surfaced doing it and are fixed here: closing an account only ever checked the cash balance — which is always zero for a brokerage — so the server accepted closing an account full of holdings and reported success; and the close/reopen cascade ran one way only, leaving half a closed account.

Standalone investment accounts and orphaned halves keep working exactly as before, and nothing about the two-row data model changed.

### The two registers behave as one

Trades on one ledger, cash on the other, drawn on both the Investments page and the account detail page — four combinations that had quietly drifted apart. Now: **every write refreshes the whole page** (create, edit, both deletes, status change, undo, redo, AI action), not just the list the row was in; **both registers page from the strip above their rows** rather than from a pager you meet only after scrolling past everything it could have saved you; **both filter in their own terms** — a trade by symbol and action, a cash row by payee and category — offering the values those accounts' rows actually use rather than the whole ledger's; and a **trade's cash leg is edited as the trade** on both pages.

The cash register on the account detail page shows its running balance, deleting a cash row no longer reports an error beside the success message, and a filter no longer throws the page back to the top.

### A reconciliation status on investment transactions

Investment transactions carry the same `UNRECONCILED` / `CLEARED` / `RECONCILED` / `VOID` status regular transactions do, with the register's existing conventions — VOID rows struck through and dimmed, one click cycling the rest — and the `.mny`, QIF and CSV importers now pass a status through to them. QIF's `C` field accepts Quicken's `c` and `R`, which previously imported silently as unreconciled.

VOID means nothing happened: no shares, no cost basis, no cash. Reconciliation states stay per-ledger, because a cash sleeve is reconciled against a bank statement independently of the brokerage — only the VOID boundary is shared. Every one of the ~30 places that reads investment transactions is now classified as an *effects* reader (share replays, cost basis, gains, valuations, net worth — excludes VOID) or a *records* reader (lists, counts, delete guards, backup export — includes it, because a VOID row is still a row), and a guard test fails on a new unclassified one.

Existing rows backfill from their cash leg, **except VOID, which backfills as unreconciled** — half-void states exist today, and silently changing holdings and net-worth history at migration time is worse than leaving the mismatch visible for you to resolve.

### Import a brokerage CSV

The CSV wizard could not import investment transactions at all. It now emits the same shape the QIF investment path produces, so the existing pipeline — security mapping, holdings, cash legs, post-processing — is reused rather than duplicated. Investment mode is detected from the file's headers with a manual toggle as the final say, and the whole configuration round-trips through your saved column-mapping presets.

Rows are classified by an action column, resolved through your own keyword lists, then built-in defaults, then the Quicken action vocabulary — by **exact** match, because substring matching over financial verbs is how "sell" claims "sell to cover taxes withheld". An action value it does not recognize becomes a cash transaction on the linked cash account by the sign of its amount, and every such value is listed back to you in the Review step; nothing is ever guessed into a trade. A missing price is derived from the row amount where that is sound and otherwise stays unknown — a buy with no derivable cost enters as uncosted shares, never at zero — and a sell with neither price nor proceeds is rejected before the commit rather than silently corrupting the balance.

### Compare against the market

**Reports → Security Performance** gains a comparison chart: cumulative returns for the securities you pick, rebased to zero at the start of the window, with curated **market indexes** (S&P 500, NASDAQ, Russell 2000 and others, grouped by region) overlaid as benchmarks. Returns use adjusted closes throughout, never mixed with raw prices for the same instrument, and a series that cannot be plotted says why rather than being quietly left out.

### Month-to-date, and what "change" is measured from

Portfolio Value and Investment charts gain an **MTD** range, and a preference in Settings → Preferences decides what the 1D, 1W and MTD figures measure their change *from*: the **prior trading day's close** (the default, and how every quote source reports a daily move) or the **first point plotted**. Longer ranges always measure from their first point, since their boundary is a calendar date rather than a session.

The "all time" charts no longer start at a 1990 epoch, and YTD opens on the first *trading* day of the year rather than 1 January, which carries December's close.

### Closing prices are closes again

The daily closing job used to skip a security that already had a price for today, on the assumption that row was the close. It was not: the app refreshes quotes through the session, so by market close the stored row was often a mid-session quote — struck at 14:42, with a running volume and a high that was only the highest so far. On real data that was 16 of 17 consecutive rows disagreeing with the provider, at a third of the real volume.

Intraday quotes are now explicitly provisional. A separate settlement pass reads the provider's **daily bars** and writes the adjusted close, only for sessions that have actually finished, and a series either carries adjusted closes throughout or none at all.

## Reports

### Account Balances, measured at a date

The report advertised balance history over a period and offered no date at all. A balance is measured at an instant, so the date is now the report's first input, defaulting to today.

Every account's ledger balance at the end of that date is computed with the same rule the live balance uses, and accounts holding securities are valued by replaying their positions and pricing them at the close standing for that date — so a position last quoted months earlier is *unpriced for the date*, not reported at a stale price. Everything is presented in your reporting currency **at the rate that stood on that date**, with the rates travelling beside the figures so the two cannot drift apart while a new date is in flight. A currency with no accepted rate for the date is left out of the totals and marked, never given a rate of 1.

If the rates or prices for an old date were never fetched, the report now asks the provider for that month, stores what comes back and re-reads — best effort, so a provider failure degrades the report rather than breaking it.

An account is excluded from the report entirely for dates **before it existed** — an asset's acquisition date, or otherwise its first real movement. Previously an asset with a purchase date showed at full value years before it was bought, and an opening balance was carried backwards past the account's first transaction to any earlier date.

The report also gains institution, account-type, open/closed and favourite filters; grouping by asset/liability, type, institution, status or favourite; sorting within each group, where an unknown balance sorts last in both directions rather than scoring as zero; and CSV export beside the PDF, both stamped with the measured date.

**Worth knowing:** the default view now shows *today's* balance. The old figure — today's balance plus every future-dated transaction, which is a projection to the end of the ledger rather than a point in time — is reachable by picking that date.

### A page for a category

Categories join accounts, payees and securities with a full detail page: period totals, key information, a **subcategory breakdown** with spending shares, **top payees**, a **tag breakdown**, **scheduled transactions** filed against the category, and a **seasonality** view of when in the year you spend on it. The Transactions tab is editable in place, the category can be edited or deleted with parent reassignment from the header, and a switcher hops to another category without going back to the list. Clicking a category in the list opens it, the way payees and accounts already worked.

### Spending totals net their refunds

A refund, return, chargeback or cashback filed against an expense category is a debit that came back, and every surface that summed only the debits put a figure on screen that disagreed with the register's own balance for the same filter — $23,212.25 reported against a $23,206.07 balance, the difference being one $6.18 credit.

Category spending is now summed over rows of both signs, so a refund reduces the category it was filed under. Reading credits at all means income reaches the aggregate, so a bucket whose net is not spending is no longer a row in a spending report — which also keeps uncategorized income out of the breakdown for the first time. Netting happens strictly *within* one category, never across two. (Payee surfaces are deliberately unchanged: they print credits as their own line beside the spend, so netting them into the headline would count them twice.)

### Cash Flow Forecast: more than one account

The forecast could show one account or all of them summed into a single line. It now takes a multi-select: no selection still means every account drawn as one filled line, exactly as before, and picking two or more draws an unfilled coloured line per account plus a **Total of Accounts** line keeping the familiar filled shape. Hovering names every selected account with its balance at that point, and says which account each listed transaction moved.

A transfer between two selected accounts moves both lines and nets to zero in the total. The total is summed in integer units from the same rounded figures the lines are drawn from, so the total on screen is exactly the total of the lines on screen. And one missing exchange rate withholds every line and the total together — the accounts that did convert are not a smaller forecast, they are a total labelled as something it is not.

### Elsewhere in Reports

- Every report detail page gets the **switcher caret** beside its title that accounts, payees, categories and securities already had, grouping fifty-odd reports by section so you can jump between them without returning to the list.
- The Accounts page's **Total Assets, Total Liabilities and Net Worth** cards now honour the *exclude from net worth* flag, so the page stops disagreeing with the net-worth series. The account *count* is unfiltered, because it counts accounts rather than money.
- Loan and mortgage accounts show **current payment, estimated payoff date and estimated remaining interest** in the transactions sidebar, derived by the same code as the loan detail page's cards — a settled debt reads "Paid off", a projection that never pays off within the horizon reads unknown, and a failed history load reads unavailable rather than projecting from nothing.

## Reconciling

The Reconcile Account screen gets four changes.

**Edit, add and delete without leaving.** Reconciling is where a missing or wrong transaction gets discovered, so the rows carry the register's own edit and delete actions and the list has an Add Transaction button. A write refetches and carries your ticked rows across by id: a row that has gone drops out instead of leaving a phantom in the selected total, and a newly listed row is ticked only when it arrives already cleared.

**Sorting and grouping.** Every column sorts, with a deterministic tiebreak so a same-day import does not re-order itself after an edit, and a toggle groups the list into money in and money out with a subtotal on each — labelled as a subtotal.

**A strict reconciled lock** (Settings → Preferences, off by default). Off keeps today's behaviour: a warning before an edit that would move a reconciled row's date or amount, then it is allowed. On, the **server** refuses — inside each mutation's own transaction, across edit, delete, split changes, bulk update and delete, transfer edit and delete, bulk reconcile, and any status change away from reconciled. Unreconciling is refused on purpose: an escape hatch one click from the row is not a lock, so the way through is the Settings toggle.

**Overdue unreconciled transactions**, treated like overdue bills. In an account you actually reconcile, a row can have been left out of a statement that was already reconciled, or have sat past a statement cycle. The register and the reconcile table highlight those rows and a header badge counts them per account, linking straight to that account's reconciliation. An account nobody reconciles has neither, whatever the age of its rows, and a failed lookup marks nothing rather than reporting an outage as a clean ledger.

## Everyday interface

### One date entry, and partial dates

The Net Worth report's custom range could not be typed into — focus was ejected after two keystrokes, and a year typed into a partly-filled field kept only its first two digits. Two causes, both of which also explain why date entry differed from screen to screen.

The desktop field was a native browser date input for one format preference and the shared text input for everybody else. The pointer decides now, not the format: touch keeps the native picker, which is the better control there, and everything else gets one field that behaves the same everywhere. And seven reports answered a load by returning a different tree, which unmounted the controls block — and the field being typed into — on every reload.

With one field and a real pattern to read against, partial dates work: `9-14` takes the current year, a lone `14` stays in the month, `4/1/26` expands, month names and any of `/ - . ,` or a space are accepted. The pattern settles what `7/8` means, and day and month are swapped only where the ordered reading names no real date. Text naming no real date restores what the field held; only an empty box means "no date".

### Row density, remembered

Density was stored thirteen different ways and three times not at all — so on the investment register a refresh, a brokerage/cash switch or navigating away and back lost the setting. There is now one store holding a map per view, so Accounts at normal while the register is dense still works, and all twelve legacy keys migrate in rather than resetting.

The toggle button existed eleven times, each reading its label from its own namespace, and the same four strings translated eight separate times had diverged: **14 of 19 locales had at least one density label that disagreed with itself across screens** — Korean "Dense" had six different translations. There is now one toggle reading one set of strings, and 420 orphaned keys are gone.

**Bills & Deposits** was the one table never wired into any of this — hardcoded padding, no toggle, about three lines per entry. It now reads the shared preference and draws the shared toggle, on its own view so tightening the register does not tighten it. The control stays on a phone, which is where a three-line row is worst.

### Smaller things

- **Create & New** on both the transaction and investment transaction forms: save and immediately reset for the next entry, keeping the account and date. The form remembers your choice for next time, separately for each form.
- **Creating a category from a split line.** A split line silently discarded text matching no category, while the same field on a non-split transaction offered to create one. Both are the same control; the split copy was missing the wiring. That needed one shared creator, and there was none — the `Parent: Child` shorthand was written out inline in two places and missing from the scheduled transaction form's third copy, so `travel: hotels` became a child of Travel in two fields and a single flat category named "Travel: Hotels" in the other.
- **Zero-amount reminders and transfers** stop disappearing from the calendars. A schedule with no amount (a reminder for a bill that varies) and a transfer between your own accounts were both being dropped by a sign check. Upcoming items are now classified four ways — bill, deposit, transfer, reminder — consistently across the bills page, budget panel, dashboard widget and Upcoming Bills report, with reminders contributing zero to totals and transfers styled distinctly.
- **Two more scheduled frequencies**: every four months and every other year.
- A currency field no longer reports a change when you focus and leave it without typing, which the transactions filter had been reading as a switch to a custom period.
- Account balances in the transactions sidebar are **coloured by sign**.
- A **joint delegate can create categories** on the owner's ledger when the owner granted it — the permission was stored, editable and reported, and reached no endpoint, so the button was withheld whatever the owner had set.
- Investment detail page actions move into the shared header row, matching every other detail page.
- The marketing site gets three mobile layout fixes, a horizontal feature strip on a phone, corrected hero image placement, and asset caching that no longer serves stale files.

## Backup and restore

- **A backup carries its own attachment bytes**, for every storage provider. Previously local and S3 attachments were metadata only, so a restore onto a fresh instance produced rows pointing at nothing. Bytes now travel in the artifact, verified by size and SHA-256 at export and again at restore, and staged before anything is deleted — so an unusable object is discovered while your data is still there. A backup taken under one provider restores under another.
- **An export cannot claim more than it holds.** Completeness is assessed before the first byte is written; an incomplete artifact says so in its filename and headers instead of reporting success, and the UI counts the unusable attachments rather than reporting nothing wrong. Restore results name **skipped** attachments separately from restored rows.
- **Exports stream.** Tables are read through database cursors in batches, JSON is serialized a row at a time under a byte budget, attachments are read one at a time, and the encrypted format writes per-frame authentication tags instead of one tag over the whole file — so peak memory tracks the chunk size rather than the size of your data. Large encrypted exports that previously hit a ceiling now complete.
- **A partial backup no longer displaces a complete one**, and an incomplete artifact is named as such rather than taking the good one's place in retention.
- **AI provider keys survive a restore onto another instance.** The stored ciphertext is encrypted under server configuration that cannot travel, so exported verbatim it restored populated and unreadable — the worst shape a failure can take, since every "is a key configured?" check said yes and the only symptom was that AI calls failed. Keys are now decrypted on the way out and re-encrypted on the way in, with what cannot be re-keyed counted and reported. The artifact then holds the credential in plaintext, which the export says plainly and the de-identified support backup drops outright.
- **Automatic backups say there is no storage configured before you set a schedule**, rather than after the first failed run — and a schedule that has started failing can now be switched off, which unavailable storage used to block.
- **A restore that fails before its transaction starts cleans up what it staged**, instead of leaving orphaned objects in the store.
- Restore **insertion order and deferred foreign keys are declared as data** and proved against the schema, so a new foreign key between backed-up tables fails a test rather than a user's restore.
- A **restore onto a database older than the code refuses up front**, naming the missing object, the migration that creates it and the remedy — instead of failing partway through with a generic 500, after the wipe has begun.

## Accounts and security

- **Logout tells the truth.** Only the server can clear the refresh cookie and invalidate the token family, but a failed logout still cleared local state, redirected and showed the usual success message — so the browser looked signed out while the server session remained usable. A failed logout now shows an error, records the fact, and the sign-in screen carries a warning with a **Retry sign-out** action until the server confirms it.
- **OIDC step-up proofs must be fresh and can be used once.** Asking an identity provider to re-prompt is not evidence it did, so the ID token's authentication time is now checked against the five-minute window and fails closed when absent, malformed, too old or implausibly in the future. Single-use is enforced across the whole deployment rather than per process, so a second replica cannot accept an artifact the first already consumed.
- **An MCP session is bound to the credential that opened it**, and relay turns are bound to sessions rather than users.
- **Emergency access works across more than one cycle.** Delivery state was recorded permanently rather than per grant, so a contact was notified at most once for the lifetime of the row — even after you returned and re-armed monitoring. Delivery state is now scoped to a grant generation that advances atomically with the grant itself, claim links are stored encrypted so a retry re-sends the same link, and the sweep coordinates across replicas with a lease rather than a permanent claim.
- **Shared Access** gets the identity its cross-user reads need under row-level security, and a **joint account cannot be re-shared onward** by someone it was shared with.
- Every user-profile response goes through **one audited allowlist**, interactive activity is attributed to the **authenticated** user, maintenance refreshes are scoped by the operation rather than the caller, and the backend **verifies its own database role at boot** — attributes, ownership and membership — refusing to serve rather than running as something unsafe.
- A CSV export's formula-injection guard no longer mangles numeric values, and screenshot names on the marketing site are resolved against a content model rather than built from the DOM.

## Microsoft Money import

Every one of these came from a real file and has a regression test.

- **A trade's cash leg is Money's, not ours.** Money pairs each investment trade with the banking row funding it. Monize imported that row *and* synthesized its own, so a register showed three rows where Money shows one, and balances moved twice. The pairings are now honoured across three distinct shapes. (#1174, #1175, #1211, #1212)
- **Seven investment activity codes** were being skipped or misfiled: reinvested interest and reinvested short- and long-term capital gains distributions now map to reinvestments; short- and long-term capital gains distributions pay into the cash sleeve; redeem CD/bond maps to a sale with the accrued-interest component reaching the sleeve; and Money's "Interest" activity is no longer misclassified. (#1149)
- **Yearly bills stopped becoming bimonthly ones**, and Money's every-four-months and every-other-year bills import at their real cadence rather than the nearest available guess. (#1150)
- A voided trade **imports fully void**, including rows with no cash leg, rather than dropping the status.
- Investment cash legs are **labelled with the activity** that produced them.
- **Register ordering** for imported rows no longer falls through to a random tiebreak.
- The **loan interest category** message that went missing during import is restored, courtesy of a first-time contributor.
- **Securities' website and investor-relations links** persist when edited. (#1122)

## Under the Hood

- **Concurrency is enforced by the database, not by checking first.** A durable job-claim mechanism (exclusive leases with expiry, delivery records, permanent claims) replaces the check-then-act patterns that two replicas, a retry or a refreshed tab could each walk through: bill and mortgage reminders, the demo reset, scheduled transaction posting, budget alerts, and the exclusion lock covering backup restore, delete-my-data and the `.mny` import. Six application-level checks became unique indexes, check constraints, fingerprints and triggers. Import workers are fenced to their attempt token so a retired job's writes are refused inside its own transaction, and attachment bytes gained a lifecycle with a lease and a quarantine for late writes.
- **Balance and transaction writes are concurrency-safe**, counted caps and the last-admin guard are acquired atomically, and auth counters, refresh-session revocation and 2FA preference writes were hardened against the same class of race.
- **Unknown is no longer zero.** Missing rates, failed valuations and unpriced holdings stay visibly distinct from a measured zero across FX conversion, portfolio summaries, allocations and Monte Carlo — which now refuses to run from an unknown starting value rather than projecting from zero. Charts draw gaps rather than fabricated points, and a cumulative forecast is withheld entirely when a missing conversion invalidates every later point. Valuation completeness reaches the **Investments frontend**, which had been rendering a subtotal under "Total Portfolio Value".
- **Cross-currency trade previews compute what the commit will do.** The `1` fallback is gone: an unresolved pair is named in the form and blocks the commit rather than previewing an invented 1:1 rate. Embedded investment splits are labelled in the security's currency with an explicit rate, and stock-split quantity replay applies one ratio definition everywhere.
- **VOID on a transfer is pair-wide.** A transfer is one movement of money in two rows, so entering or leaving VOID writes both legs and both balances in one transaction — through the single-status endpoint, bulk updates and transfer editing alike — while `CLEARED`, `RECONCILED` and the reconciled date stay on the leg the caller is actually changing. Two stored legs that already disagree fail closed rather than compounding.
- **The contract documents.** `docs/system-invariants.md` indexes every invariant with a stable ID, the mechanism enforcing it, and a status of `enforced`, `partial` or `unenforced` — an entry marked unenforced describes something the system currently gets wrong, with the violation cited, and editing the document does not close it. Alongside it: concurrency and idempotency, financial semantics, external side effects, backup and restore, row-level security, verification, release integrity, and the first three architecture decision records.
- **Rules that a machine can check became checks.** `DataSource.transaction()` is banned outright and the documented ban list is verified; migration prefixes are gated for uniqueness and ordering; the test tree is type-checked (four E2E suites had not compiled since 27 July); setup and deploy documentation is checked against the manifests; repository paths named in Markdown, TypeScript and SQL comments must resolve; the pre-login localStorage footprint is guarded against expansion; and the auto-backup suite's clock is pinned so it stops testing today's date.
- **Startup got quieter and stricter.** Startup database work is serialised, the runtime role is verified before serving, every SQL function the code calls is declared with the migration that creates it and refused if absent, and all startup logging goes through the standard logger rather than raw console writes.
- **Releases are bound to their tested revision**, and the Helm chart is linted and rendered in CI — nothing had ever executed it.
- **`BackupService` is split into focused components**, the RLS exemption list is consolidated into one place with the `oauth_payloads` boundary documented, AI query budgets are configurable and scoped to the provider they were configured for, and import job reaping became demand-driven so a stale job no longer locks a user out for five minutes.
- New database migrations: **136–137** (currency reference functions), **138** (market index prices), **139** (AI provider query budgets), **140–143** (concurrency guards, job claims, lease tokens and their enforcement), **144–145** (import attempt token and checkpoint fence), **146–148** (attachment upload leases and late-write quarantine), **149–151** (emergency access delivery state, grant generation, rotation fence), **152–153** (portfolio change baseline), **154** (loan extra payment), **155** (OIDC step-up claims), **156** (every-four-months and every-other-year frequencies), **157** (investment transaction status), **158** (Money investment action variants), and **159** (the strict reconciled lock preference).
